# ArUco 地标打印与放置

本指南与 `config/aruco-landmarks.json`、`config/aruco-lab.example.json` 使用同一套几何定义。适用于完整 15 舵机 Microduck 的首轮地标定位实验。位置是建议搭建的实验布局，不是对你房间的测量结果。

## 1. 打印四张完整 A4 地标

打印交付的 ArUco 标记 PDF，前四页每页一个 ID，共 **0、1、2、3** 四张；第 5 页是单独的相机标定棋盘。优先直接打印矢量 PDF，不要把聊天截图、缩略图或预览页当作打印源。

| 项目 | 本套标记的精确约定 |
|---|---|
| 字典 | `DICT_4X4_50` |
| 标记 ID | `0`、`1`、`2`、`3`，各使用一张 |
| 黑色方块外边长 | **160 mm × 160 mm**，包含外侧黑边 |
| 字典内部编码 | 4 × 4 位，外侧黑边 `borderBits=1` |
| 白色留白 | 黑方块外侧各方向至少 **20 mm**，不要在其中画线或贴胶带 |
| 纸张 | A4 纵向，210 mm × 297 mm |
| 打印缩放 | **实际尺寸 / 100%**，关闭“适合页面”“缩小超大页面”等缩放 |
| 校验条 | 每张纸的 100 mm 标尺，打印后用实体直尺测量 |
| 方向 | 纸上的 `TOP` 箭头始终指向真实竖直上方 |

`size_m = 0.16` 指的是**整个黑方块的外边长**，不包括白色留白、A4 纸张或标题。OpenCV 使用这个长度确定距离尺度，不能把整张纸宽度填成 marker size。

打印后分别测量黑方块横边、竖边和 100 mm 校验条。建议各自偏差不超过 0.5 mm；若有明显缩放，先修正打印设置。若横竖缩放不一致，必须重新打印，不能用一个 `size_m` 补偿。使用哑光白纸，贴在平整硬板上，避免折痕、卷边和反光覆膜。保留整张纸即可，无需裁切；如果裁切，仍须保留至少 20 mm 白边。

不要在同一场景中重复放置同一个 ID。若保留旧打印页作备份，把它翻面或放到相机视野外。

## 2. 地面坐标与四块竖直板

在平整地面上选定中心点，用普通胶带标一个十字作为 **O=(0,0,0)**。这个十字不是另一个 ArUco 标记。

- 从 O 指向 **ID 0** 的地面方向定义为世界 **+X**。
- 从 O 指向 **ID 1** 的方向定义为世界 **+Y**；站在 O 面向 ID 0 时，它在左侧。
- **+Z** 竖直向上。机器人 yaw=0 表示机身朝向 ID 0；向左转为正 yaw。

四张纸都竖直安装，**印有黑方块的一面朝向 O**。每张纸的 TOP 向上，纸面不得绕竖直轴斜向旁边，也不得前倾或后仰。

| ID / 目标标签 | 黑方块中心坐标 `(X,Y,Z)`，单位 m | 放置位置 | 印刷正面朝向 |
|---|---|---|---|
| 0 / `marker_0` | `(1.20, 0.00, 0.20)` | +X 侧，首轮前方目标 | −X，面向中心 |
| 1 / `marker_1` | `(0.00, 1.20, 0.20)` | +Y 侧，起始朝向的左侧 | −Y，面向中心 |
| 2 / `marker_2` | `(−1.20, 0.00, 0.20)` | −X 侧，起始朝向的后方 | +X，面向中心 |
| 3 / `marker_3` | `(0.00, −1.20, 0.20)` | −Y 侧，起始朝向的右侧 | +Y，面向中心 |

坐标指**黑方块中心**，不指纸角或支架脚。用卷尺测量中心点在地面的投影到 O 的距离：四块板均为 1.20 m；相对两板中心投影之间为 2.40 m。中心离地 0.20 m，因此黑方块下缘离地 0.12 m，上缘离地 0.28 m。

交付页面把黑方块中心安排在距 A4 下边缘 160 mm 处，所以按这套 0.20 m 中心高度放置时，**整张纸的下边缘离地 40 mm**。仍应直接复测黑方块中心高度，避免裁纸或打印缩放改变这个关系。

活动区是 O 周围 **2.00 m × 2.00 m**，即 `X,Y∈[-1,1] m`。Gateway 的边界余量为 0.20 m，因此机身参考点实际允许范围为 `X,Y∈[-0.8,0.8] m`。四块板在活动区外侧 0.20 m；支架、纸板和其他物体均不应伸入活动区。布置板及支架需要比 2 m × 2 m 更大的可用地面。

首轮放置时，可只安装 ID 0 并完成其定位与靠近实验，再按表加入其余三块。所有板的位置只要与配置一致即可；改变任何板的位置、高度或朝向后，必须更新对应 `T_world_marker`。

## 3. 这套配置如何解释纸面的方向

OpenCV 标记坐标采用纸面中心为原点：从正面看，局部 `+x` 向右、`+y` 向上、`+z` 从纸面指向读者。`T_world_marker` 把这个标记坐标转换到上面的地面世界坐标。

每个矩阵的前三列分别是标记局部 x、y、z 轴在世界坐标中的方向，第四列是中心坐标。例如 ID 0：

```json
[
  [ 0, 0,-1, 1.2],
  [-1, 0, 0, 0.0],
  [ 0, 1, 0, 0.2],
  [ 0, 0, 0, 1.0]
]
```

它表示纸面右侧为世界 −Y、纸面上侧为世界 +Z、正面法线为世界 −X。其余三张的矩阵已写在 JSON 中，不必手工计算。

虽然 ArUco 能识别旋转后的编码，但定位仍然依赖配置中的地标朝向。因此不能把打印页横贴 90° 而沿用原来的矩阵。也不要把正面朝向中心的板换成背面朝向中心。

## 4. 相机与网络配置

复制 `config/aruco-lab.example.json` 为本机工作配置。它已经包含正确的字典、4 个 ID、黑方块尺寸、地标标签与世界变换，使用 `mode="camera"`。

**仍需填写真实标定参数：**

- `camera_matrix`：3 × 3 相机内参。
- `distortion`：相机畸变参数。
- `image_size`：这些内参对应的原始图像宽高。

示例中这些测量没有被伪造。OpenCV 的姿态估计需要内参与实际标记尺寸；打印标记不能替代相机标定。

robotd 0.16.3 与 0.17.8 均提供 `frames.camera` 和 `frames.tof`。标准装配默认使用与采集时刻配对的原生动态 FK。若相机安装位置与官方模型不同，需校准实际相机到机身的变换；固定头部回退方式还需填写 `T_body_camera` 和 `fixed_head_rad`，不能直接照抄软件测试里的外参。

原始 UYVY 图像、相机内参和动态 FK 必须使用同一个像素坐标约定。默认 `rotate_upright=false`；不要因为预览看起来倒置就单独旋转图像而保持原内参和 FK 不变。

电脑和 ZERO 处于同一 Wi-Fi 时，三项地址应指向 ZERO 的真实地址：

```text
camera_url = http://ZERO的实际IP:8766/frame
state_url  = http://ZERO的实际IP:8766/state
tof_url    = http://ZERO的实际IP:8766/tof
```

这三项在 JSON 示例中保留 `127.0.0.1`，适用于已有 SSH 转发。直接 Wi-Fi 连接需要同时替换三个地址；`127.0.0.1` 在电脑上表示电脑本身，不表示 ZERO。认证使用 `EXECUTOR_TOKEN` 环境变量，和板端保持一致。路由器的访客网络或客户端隔离会阻断同 Wi-Fi 设备互通，连接前应通过 `/health`、`/state` 核对实际设备。

## 5. 用第 5 页棋盘获得真实相机内参

打印包中的独立棋盘是 **9 列 × 6 行方格，每格 20 mm**，总黑白图案为 **180 mm × 120 mm**。OpenCV 输入的是**内部角点 8 × 5**，不要把它填成方格数 9 × 6。测量单格 20 mm、连续五格 100 mm 和图案总宽 180 mm；关闭打印缩放，并将纸贴在平整硬板上。棋盘不含 ArUco ID，不是世界地图中的第 5 个地标。

先在电脑安装视觉依赖（已安装可跳过），确保板端 executor 已按真机文档启动，`EXECUTOR_TOKEN` 已在当前终端环境中设置。采集脚本只读取 `/frame`，不会启用舵机或发送运动指令。按既有真机流程保持机器人不行走，移动棋盘来改变观测角度。

```bash
python -m pip install -e '.[vision]'
python scripts/calibrate_camera.py capture \
  --executor-url http://ZERO_IP:8766 \
  --directory data/calibration-raw
```

把 `ZERO_IP` 换成 ZERO 的真实 Wi-Fi 地址；采用 SSH 转发时可用 `127.0.0.1`。脚本提示后，每按一次 Enter 只保存一张原生 PNG，输入 `q` 结束。图像保持相机原始宽高和原始方向，不缩放、不裁切、不旋转；即使预览倒置也保持这个约定。已经有同一相机、同一分辨率、同一像素方向的原始 PNG，也可直接放进该目录，不必再次采集。

建议采集 **20–30 张清晰图像**，从中至少得到 12 个完整、不同的视角。让棋盘分别位于画面中央、左上、右上、左下、右下附近；在保持全部角点可见时改变距离与左右、上下倾斜角度。每次稳定后再拍，避免运动模糊、强反光和折弯。只在相同位置连拍 20 张，不构成 20 个有效标定视角。不要混入不同分辨率、经过屏幕截图缩放或改变相机焦距后的图片。

```bash
python scripts/calibrate_camera.py calibrate \
  --images data/calibration-raw \
  --output data/camera-calibration.json
```

脚本使用 OpenCV 棋盘角点检测和 `calibrateCamera`，去除字节完全相同及角点位置几乎不变的重复图像；少于 12 个视角、图像尺寸不一致或数值无效会报错。结果包含：

- `camera_matrix`、`distortion`、`image_size`，对应原始图像。
- 总体重投影 RMS 和逐张图片 RMS，单位为像素。
- 接受/拒绝的图像清单，以及画面覆盖、距离变化和误差提示。
- `needs_physical_validation=true`，表示仍需现场独立验证。

12 张只是最低数量，不保证视角充分；低重投影误差也不证明真实位置准确。检查误差异常的原图、棋盘平整度和角点覆盖，并用未参与求解的图片复查。标定后仍需进行下一节的 ArUco 尺度与方向检查。单块平面标记较远、像素较少或近乎正面时，位姿对很小的角点误差也可能敏感；系统已启用亚像素角点细化，但不能据此承诺厘米级实测精度。

脚本只创建新的标定结果；不会覆盖同名已有文件，也不会自动修改正在使用的 vision 配置。审核结果后，**把 `camera_matrix`、`distortion`、`image_size` 三项明确复制到你的工作配置**，例如 `config/aruco-lab.local.json`，保留已核对的地标地图、URL 和其他字段。相机镜头、分辨率或像素旋转方式变化后应重新标定；镜头内参标定不会测出相机到机身的安装外参。

## 6. 首轮检查顺序

1. **静态辨识。** 按既有真机流程保持不行走，将机器人置于 O 附近、朝向 ID 0。读取观测，确认检测 ID 为 `marker:0`、标签为 `marker_0`，而不是其他 ID。
2. **原点检查。** 标定正确时，机身参考点的水平位置应接近 `(0,0)`，yaw 接近 0。目标水平距离应接近机身参考点到板中心投影的实际距离；位于 O 时约 1.20 m。
3. **符号检查。** 在不启用自主运动时按既有真机操作流程改变摆放位置。向 ID 0 平移 0.20 m 后，x 应增加约 0.20 m、marker_0 水平距离约降至 1.00 m。向 ID 1 方向平移 0.20 m，y 应增加约 0.20 m；机身仍朝 +X 时，ID 0 会出现在右方，bearing 应为负。
4. **朝向检查。** 只在传感与真机操作已验证的条件下，检查面向 ID 1 时 yaw 是否接近 `+π/2`。面向 ID 2 为 `±π`，面向 ID 3 为 `−π/2`。位置应与实际摆放一致，不能因切换可见地标而大幅跳变。
5. **已可见目标确认。** 原生策略须已按已有流程处于健康的 `stand` 或 `walk` 状态，保持 `EXECUTOR_ALLOW_MOTION=0`，再提交“寻找 marker_0”。已可见标记可由连续新鲜图像确认；任务启动与结束仍会请求停止行走，因此这不是纯只读接口。完全未启用策略、放松或被抱起时，即使看到标记也可能被阻止。真正只读请使用工作台状态或 GET 观测；不要把查找成功解读为移动完成。
6. **短距离靠近。** 从 O 朝 ID 0 提交“靠近 marker_0 并停下”。真机示例到达距离为机身参考点至标记的水平距离 0.55 m，预计在 x≈0.65 m 处完成；这个数值必须以实际定位和 ToF 约束为准，不是执行器保证的真实终点。

若静态位置方向反了、跳变、范围明显不对或停止位置无法达到，先修正打印尺度、板姿态、内参或坐标配置，不要放宽运动检查掩盖问题。可以先运行配置检查脚本：

```bash
python scripts/check_aruco_setup.py --config config/aruco-lab.local.json
```

把路径替换成自己的工作配置；直接检查尚未填写内参的 `config/aruco-lab.example.json` 时，它会明确返回“未就绪”，不会把模板当作完成标定。打印后可额外输入实体测量值检查尺度：

```bash
python scripts/check_aruco_setup.py --config config/aruco-lab.local.json \
  --printed-width-mm 160 --printed-height-mm 160 --scale-bar-mm 100
```

## 7. 可见范围与后续探索

四块板是首轮定位基准，**不保证整个活动区、所有朝向都连续可见地标**。相机视场、实际焦距、分辨率、遮挡和距离都会影响检测。原地转向到两块板之间时，可能出现无地标画面；此时 `pose_valid=false`，当前运动应停止。不能用上次位置加新时间戳来假装定位仍有效。

先完成 ID 0 的静态定位、寻找和靠近，再检查不同位置、方向的地标覆盖。需要持续转向和更大范围自主探索时，再根据实测视场增加不同 ID 的已测量地标，或接入经过验证的连续定位。单次 ArUco 定位和前方 ToF 也不等于完整避障或桌边检测。
